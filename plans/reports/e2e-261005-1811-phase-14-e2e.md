## Render-check

`apps/web/e2e/render-check.spec.ts`, project `render` (`pnpm render-check`, not part of `test:e2e`). The prototype is served by `python3 -m http.server` on 127.0.0.1:8090 for the duration of the run; port 8090 was free again afterwards.

17 routes (every route in `plan.md` §8 that has a prototype counterpart; `/reset-password` has none) × 3 viewports (1440×900, 768×1024, 375×812): **17/17 pass**.

What fails the test, per route and viewport:

- Computed style equal to the prototype: topbar background (`rgb(35, 60, 101)`), active nav border (`rgb(244, 93, 41)`), primary gradient (`linear-gradient(260deg, …)`), body font family, size (15px) and background (`rgb(245, 245, 245)`), card radius and shadow, text input height.
- At most one gradient action on the page.
- Layout: no horizontal overflow, no clipped text, no text under 12px.

Results and exceptions:

- **Card shadow.** Tailwind composes `box-shadow` with four transparent zero layers; they are dropped before the comparison. The remaining layer equals the prototype (`rgba(0, 0, 0, 0.15) 0px 0px 7px 0px`).
- **Card radius.** The plan says 3px; the prototype `.card` has radius 0 and so does the web card. The test compares with the prototype.
- **11px tags (decision needed).** `Badge` (`data-slot="badge"`, 11px) matches the prototype `.badge` and the phase-10 spec, but conflicts with the "no text under 12px" rule in `docs/design.md` and success criterion 7. The test does not count badges as defects; it records them as `tag-11px` annotations (33 route × viewport combinations). No other text under 12px was found.
- **Navy primary on two tabs.** On `admin-class-students` ("Mời học viên") and `admin-class-settings` ("Lưu thay đổi") the prototype uses the gradient, while phase 12 specifies `Button default` (navy): on a draft class "Kích hoạt lớp" is already the page's gradient. The test asserts navy on exactly those two routes and records a `navy-primary` annotation. Every other route's gradient equals the prototype.
- **Region screenshots.** Topbar, page head, first card and first table are screenshotted on both sides; the prototype image is the baseline and the web image is compared at `maxDiffPixelRatio: 0.02`. A mismatch is recorded as a `render-diff` annotation rather than a failure, because the two sides show different data (the prototype topbar carries the demo role switcher, row counts and text lengths differ). 102 region comparisons exceed 2%: the topbar on every signed-in route (4% desktop, 10% at 375px, the role switcher) and cards and tables whose heights differ with the data. The largest is the lesson card (53–81%): the prototype's first card on the lesson page is the progress box, the web's is the lesson body.
- Full-page screenshots are written to `apps/web/e2e/__screenshots__/<route>/<viewport>.png` and `apps/web/e2e/__screenshots__/prototype/<route>/<viewport>.png` (git-ignored). The plan's `prototype/<route>/…` path would write into the prototype folder, which this phase does not own.
- The skill script `render-check.mjs` takes no cookies, so the Playwright version above applies the same criteria (0 overflow, 0 clipping, 0 text under 12px), as the plan allows.

## Defects fixed

Each fix is in the owning feature and has a test that fails without it.

1. **FR-17 apply wrote three audit rows with different timestamps.** `course.stage_version_applied`, `course_version.cloned` and `course_version.published` now share the transaction's single `at`, as E04 requires. Files: `apps/api/internal/platform/audit/audit.go`, `apps/api/internal/platform/audit/pg.go`, `apps/api/internal/platform/audit/pg_integration_test.go`, `apps/api/internal/features/courses/service.go`, `apps/api/internal/features/courses/apply.go`, `apps/api/internal/features/courses/apply_test.go`.
2. **Video lost its position after two errors in a row.** When the re-signed element also failed before loading, it reported position 0 and overwrote the saved one. The pending position is now kept (`??=`). Files: `apps/web/src/features/learning/components/video-player.tsx`, `apps/web/src/features/learning/components/video-player.test.tsx`.
3. **Dialogs did not give focus back on close (E30).** Every app dialog opens from state, not from a Radix `DialogTrigger`, so Radix had nothing to refocus and focus fell to `body`. `DialogContent` now remembers the focused element on open and restores it on close if it is still on the page. This covers every dialog. Files: `apps/web/src/shared/ui/dialog.tsx`, new test `apps/web/src/shared/ui/confirm-dialog.test.tsx`.
4. **Dropped members' rows failed contrast (axe `color-contrast`, E32).** The rows were faded with `opacity-60`, which took the grey secondary text below 4.5:1. They are now tinted with `bg-surface-100` instead. Files: `apps/web/src/features/classes/components/member-row.tsx`, `apps/web/src/features/reports/components/report-table.tsx`, tests `students-tab.test.tsx` and `report-panel.test.tsx`.
5. **Report filter controls were 40px instead of the prototype's 36px (render-check).** The plan names `form.filter-bar`, whose inputs, select and checkbox labels are 36px on desktop and 44px on touch screens. The filter bar now uses 36px (`h-9`) on desktop and keeps 44px and 16px text at ≤720px. Files: `apps/web/src/features/reports/components/filter-bar.tsx`, test in `report-panel.test.tsx`.
